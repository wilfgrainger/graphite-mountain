The operating system

A lifecycle designed to reopen when reality disagrees.

Each stage creates a concrete pack, passes an evidence gate, and retains traceability to the outcome.

Mission, users, journeys, current state, constraints, acceptance, risk, proof, and vertical work units.

Architecture

Gate: coherent enough to build

Construct & verify

Gate: release candidate ready
04

Deploy & operate

Authority, rollout, real-environment validation, observability, rollback, recovery, and handover.

Gate: delivered and operable

Start with the job

Choose the smallest mode that can materially change the outcome.

Use the full lifecycle for substantial delivery. Use a focused mode when the decision boundary is already clear.

full-teamDesign and deliver

New substantial work

Requirements, architecture, complete construction, independent review, release evidence, and operational handover.

Use Graphite Mountain in full-team mode. Start with the guided intake, ask no more than three questions at a time, and pause for confirmation before each lifecycle gate.
reviewInspect actual state

Existing repository review

Rank evidence-led findings, identify the smallest valuable corrections, and return one reconciled verdict.

Use Graphite Mountain in review mode. Start by confirming the target, current state, authority, and success criteria before ranking improvements.
autoloopImprove by evidence

One measurable experiment

Set a baseline, test one hypothesis, run the numeric evaluator and regressions, then retain or reject the candidate.

Use Graphite Mountain in autoloop mode. Require a baseline, metric direction, model and run budget, one hypothesis, one candidate change, deterministic evaluation, regression checks, and a bounded stop condition. Keep only measured gains; never merge or deploy automatically.
rescueRecover momentum

Stalled or contradictory work

Reconstruct the truth, stabilise the current state, narrow the scope, and deliver the next decisive proof point.

Use Graphite Mountain in rescue mode. Ask what is blocked, what is verified, and what authority exists, then deliver the next decisive proof point.

Also available: requirements, architecture, construct, release, intake, goal, issue-forge, review-loop, and any named team member.

Model guidance

Choose by risk. Prove the trade-off.

Model names change; capability profiles and evidence last longer. Use the strongest reasonable model for ambiguity, a coding model for bounded execution, and a deterministic evaluator for Autoloop decisions.

Six distinct lenses

Equal challenge rights. Explicit accountability.

Canonical roles own decision domains, methods, evidence standards, and review focus. The v0.x profile aliases remain only for compatibility with existing invocations.

JDelivery chair

Delivery Chair Jared

Product outcome, scope, ownership, sequencing, commitments, decisions, launch, and coherent final recommendation.

Is the mission valuable, bounded, owned, affordable, and provable?
RArchitecture lead

Architecture Lead Richard Hendricks

Invariants, architecture, algorithms, representation, performance, feasibility, and ethical boundaries.

Which constraint or invariant actually decides the approach?
DEngineering lead

Engineering Lead Dinesh

Complete product paths across UI, services, integrations, data, migrations, tests, and developer experience.

Which complete user or caller path must work?
GPlatform and safety

Platform and Safety Lead Gilfoyle

Security, infrastructure, capacity, CI/CD, observability, deployment, rollback, restore, and recovery.

Which failure or recovery path decides whether this is safe?
JYAdversarial strategy

Adversarial Strategy Lead Jian-Yang

Incentives, ownership, dependencies, claims, copyability, substitution, platform power, and metric gaming.

How can a motivated actor route around the intended outcome?
ECustomer advocate

Customer Advocate Erlich Bachman

Customer discovery, usability, accessibility, positioning, onboarding, adoption, support, and narrative.

Will the intended customer understand, trust, use, and recommend it?

Triggered advisors keep the model honest when the work needs Legal / Privacy Counsel, Data / Evaluation, Product Design / Accessibility, or Release / Support Operations. They add evidence and escalation without turning every specialist lens into a permanent persona.

A professional operating model

Evidence sets the pace.
Human judgment owns the gates.

  • Evidence before confidence. Facts, results, inferences, assumptions, decisions, risks, and unknowns are labelled.
  • Complete journeys over isolated activity. A polished function nobody can reach is still decorative computing.
  • Recovery is designed, not wished for. Deployment, rollback, restore, and ownership exist before launch.
  • No public claim stronger than the proof. Marketing adjectives do not pass lifecycle gates.

Start using it

Install once. Invoke it in plain English.

The skill is plain Markdown: clone or download the repository, then load the skill folder through your agent runtime. The command below is the Claude Code macOS / Linux path; Windows PowerShell instructions and direct-path guidance are in the README.

macOS / Linux terminal 
tmp="$(mktemp -d)"
git clone --depth 1 https://github.com/wilfgrainger/graphite-mountain.git "$tmp/graphite-mountain"
mkdir -p ~/.claude/skills
cp -R "$tmp/graphite-mountain/skills/graphite-mountain" ~/.claude/skills/
rm -rf "$tmp"

Windows PowerShell and platform-neutral direct-path instructions: see README.md.
